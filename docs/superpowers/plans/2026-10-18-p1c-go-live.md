# P1-C Claiming, approvals, go-live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the shared Glasshouse server safe to put in front of the whole team on company infrastructure: one editor per room draft at a time, approved revisions that can't change, a server that recovers from database hiccups and refuses to run twice, readable verified names, and a Docker deployment in the company's own compose pattern with nightly backups and a rehearsed restore.

**Architecture:** Room claims are soft locks held in the server's memory (a `ClaimRegistry`), enforced inside `WorkspaceService.submit` for draft edits, and broadcast on the existing event stream. Approval immutability is a pure domain check (`approvedRevisionChanges`) run by the server after every command, plus a content fingerprint stored on the revision and an append-only `approvals` table written in the same transaction as the command. Operations add `/api/ready`, a session-level Postgres advisory lock, recovery from an ambiguous log append, security headers, and a multi-stage Docker image with a compose file modelled on the company's db-playground deployment.

**Tech Stack:** TypeScript, Fastify 5, `@fastify/helmet`, Postgres 18 (`pg`), React 19 + zustand, `@noble/hashes` (sha256 in the shared domain), Vitest, Playwright, Docker / docker compose, Traefik labels.

**Spec:** `docs/superpowers/specs/2026-10-17-p1-shared-server-design.md` (sections "Conflicts", "Approvals, import, operations (Plan C)", "Delivery", and the Plan A / Plan B "carried into Plan C" paragraphs). Company infrastructure facts come from the product owner's samples (db-playground compose, Authelia 4.39 configuration) summarised under Global Constraints.

## Decisions taken in this plan (product owner may overrule)

1. **Claiming is automatic.** The first accepted edit to a room's draft claims it for that person; each further edit renews it. The holder releases with "Done editing", by leaving the room, by submitting it for review, or by discarding the draft. After 15 minutes without an edit any Editor may take over; an Admin may take over at any time. Claims live in server memory: a restart clears them and the next edit claims again. Dev mode (no sign-in) has no claims.
2. **A lost claim never loses work.** When someone takes over, the previous holder's unsent edits to that room are refused; before dropping them their browser offers "Download my version" (a Project file of their version, importable later as a copy).
3. **Approved means unchangeable on the server.** Any change that alters or removes an approved revision of a room that still exists is refused (including a "take incoming" import over it). Deleting a room, site or project stays as the role matrix allows; the `approvals` table keeps the approval record and fingerprint forever.
4. **Fingerprint** = sha256 of the revision's canonical content; the first 12 hex characters are shown on the review panel and the Install sheet.
5. **Names.** A verified person is shown with their current name from the Users list and their email ("Ploy Sriwan (ploy@oxygenai.com)"). An admin can set a full name; later company sign-ins no longer overwrite it.
6. **Backups.** A `backup` container runs `pg_dump` daily at 03:00 Asia/Bangkok into `/data/services/services-data/glasshouse/backups`, keeping 14 days; admins can also download a workspace backup from the app.
7. **Queued features** (weight and floor load, measured/assumed values) become Plan D, before the pilot. Install-day verification stays after go-live.

## Review Focus

1. **Takeover while the old holder is offline with queued edits.** When they reconnect, every queued edit to that room must be refused and the "Download my version" offer shown once. Nothing may be applied over the new holder's work, and nothing may vanish without the offer. Pinned in Task 4 (server refuses) and Task 5 (client offers the download).
2. **An ambiguous log append.** The insert committed but the server saw an error, so the client retries. The server must not wedge on the next seq, and must apply the command exactly once. Approvals and commands must stay consistent: both rows or neither. Pinned in Tasks 2 and 3.
3. **A "take incoming" import over an approved revision.** It must be refused with a message naming the room and revision; importing the same file as a copy still works. Pinned in Task 2.
4. **A second server container started by mistake** (an old container, or `docker compose run web`). It must refuse to start with a clear message while the first keeps serving. Pinned in Task 3 (unit) and Task 9 (smoke script).
5. **Security headers.** The CSP must not break the real app: home, plan, 3D view, Install sheet and sign-in screen must render with no CSP violation in the console. Pinned in Task 8 (server e2e).

- [ ] **Step 9: Implement approvedRevisionChanges**

`packages/domain/src/approvals.ts`:

```ts
import { canonicalJson } from './canonical';
import { findRoom } from './lookup';
import type { Id, Workspace } from './model/types';

export interface ApprovedChange {
  roomId: Id;
  roomName: string;
  revision: number;
}

/**
 * Approved revisions that `after` altered or removed while their room still exists. An approved revision is a
 * record: the whole revision (content, people, times, fingerprint) must come through byte-identical.
 */
export function approvedRevisionChanges(before: Workspace, after: Workspace): ApprovedChange[] {
  const changes: ApprovedChange[] = [];
  for (const project of before.projects) {
    for (const site of project.sites) {
      for (const room of site.rooms) {
        const now = findRoom(after, room.id);
        if (!now) continue;
        for (const rev of room.plan.revisions) {
          if (rev.state !== 'approved') continue;
          const same = now.room.plan.revisions.find((r) => r.number === rev.number);
          if (!same || canonicalJson(same) !== canonicalJson(rev)) changes.push({ roomId: room.id, roomName: now.room.name, revision: rev.number });
        }
      }
    }
  }
  return changes;
}
```

Check that `findRoom` in `lookup.ts` returns `{ room, site, project } | null`; adapt the property access if it differs. Export from `index.ts`. Run: PASS.

Performance note for the reviewer: the server runs this after every accepted command. `canonicalJson` of every approved revision is linear in workspace size, the same order as the `parseWorkspace` validation it already runs (1.5 ms for the two-sample workspace). If the domain suite's timing test or your measurement on the sample workspace shows this above 5 ms, compare `rev === same` by reference first; immer keeps untouched subtrees identical, so skip the canonical comparison when the references are equal.

/** A hand-edited file can move a room to another site; merging would then keep both copies under one ID. */
function duplicateId(p: Project): { id: Id; name: string } | null {
  const seen = new Set<Id>();
  for (const s of p.sites) {
    if (seen.has(s.id)) return { id: s.id, name: s.name };
    seen.add(s.id);
    for (const r of s.rooms) {
      if (seen.has(r.id)) return { id: r.id, name: r.name };
      seen.add(r.id);
    }
  }
  return null;
}

/** Applies logged commands after `from` to `workspace`; throws on a gap or a command that won't apply. */
async function replayAfter(store: CommandStore, from: { seq: number; workspace: Workspace }, onEntry: (e: LoggedCommand) => void = () => {}): Promise<{ seq: number; workspace: Workspace }> {
  let { seq, workspace } = from;
  for (;;) {
    const page = await store.commandsAfter(seq, REPLAY_PAGE);
    if (page.length === 0) return { seq, workspace };
    for (const entry of page) {
      if (entry.seq !== seq + 1) throw new Error(`The command log has a gap after seq ${seq} (next is ${entry.seq}).`);
      const result = apply(workspace, entry.command);
      if (result === undefined) throw new Error(`Replaying seq ${entry.seq} failed: unknown change type "${entry.command.type}".`);
      if (!result.ok) throw new Error(`Replaying seq ${entry.seq} failed: ${result.error.message}`);
      workspace = result.value;
      seq = entry.seq;
      onEntry(entry);

  }
}

`pgStore.ts`:

```ts
/** Distinct from the migration lock (727274): held for the whole life of the process. */
const INSTANCE_LOCK_KEY = 727275;

export class InstanceLockError extends Error {}

  private constructor(private readonly pool: pg.Pool, private readonly lock: pg.PoolClient) {}

  static async connect(url: string, { onLockLost = defaultLockLost }: { onLockLost?: (error: unknown) => void } = {}): Promise<PgCommandStore> {
    const pool = new pg.Pool({ connectionString: url, max: 6 });
    pool.on('error', (e) => console.error('Postgres connection error', e));
    await migrate(pool);
    const lock = await pool.connect();
    const r = await lock.query<{ ok: boolean }>('select pg_try_advisory_lock($1) as ok', [INSTANCE_LOCK_KEY]);
    if (!r.rows[0]?.ok) {
      lock.release();
      await pool.end();
      throw new InstanceLockError('Another Glasshouse server is already running against this database. Only one may run at a time (P1 design): stop the other one first.');
    }
    // If this connection drops, Postgres frees the lock and a second server could start: stop rather than run unguarded.
    lock.on('error', onLockLost);
    return new PgCommandStore(pool, lock);
  }

  async close(): Promise<void> {
    await this.lock.query('select pg_advisory_unlock($1)', [INSTANCE_LOCK_KEY]).catch(() => undefined);
    this.lock.release();
    await this.pool.end();
  }
```

with

```ts
const defaultLockLost = (error: unknown): void => {
  console.error('Lost the database connection that holds the single-instance lock; exiting so the container restarts cleanly.', error);
  process.exit(1);
};
```

`max` goes from 5 to 6 because one connection is permanently held. The `close` catch is deliberate: closing must finish even if the lock connection is already broken, and Postgres frees a session lock when the connection ends anyway.

/** After this long without an edit, any editor may take a room over (P1 design, "room draft claiming"). */
export const CLAIM_IDLE_MS = 15 * 60 * 1000;

export interface Claim {
  roomId: string;
  userId: string;
  name: string;
  since: string;
  lastEditAt: string;
}

type Listener = (claims: Claim[]) => void;
interface Person {
  id: string;
  name: string;
}

/**
 * Who is editing which room's draft. Soft locks in memory: a restart clears them and the next edit claims again.
 * Single instance by design, so no cross-process coordination.
 */
export class ClaimRegistry {
  private readonly claims = new Map<string, Claim>();
  private readonly listeners = new Set<Listener>();

  constructor(private readonly now: () => Date = () => new Date()) {}

  list(): Claim[] {
    return [...this.claims.values()];
  }

  holder(roomId: string): Claim | null {
    return this.claims.get(roomId) ?? null;
  }

  canEdit(roomId: string, userId: string): boolean {
    const held = this.claims.get(roomId);
    return !held || held.userId === userId;
  }

  idle(claim: Claim): boolean {
    return this.now().getTime() - Date.parse(claim.lastEditAt) >= CLAIM_IDLE_MS;
  }

  /** An accepted draft edit: claims a free room or renews the holder's claim. Callers check canEdit first. */
  touch(roomId: string, user: Person): void {
    const at = this.now().toISOString();
    const held = this.claims.get(roomId);
    this.claims.set(roomId, held && held.userId === user.id ? { ...held, name: user.name, lastEditAt: at } : { roomId, userId: user.id, name: user.name, since: at, lastEditAt: at });
    this.changed();
  }

  claim(roomId: string, user: Person, { admin }: { admin: boolean }): { ok: true; claim: Claim } | { ok: false; claim: Claim } {
    const held = this.claims.get(roomId);
    if (held && held.userId !== user.id && !admin && !this.idle(held)) return { ok: false, claim: held };
    const at = this.now().toISOString();
    const claim = held && held.userId === user.id ? { ...held, lastEditAt: at } : { roomId, userId: user.id, name: user.name, since: at, lastEditAt: at };
    this.claims.set(roomId, claim);
    this.changed();
    return { ok: true, claim };
  }

  release(roomId: string, userId: string, { admin }: { admin: boolean }): boolean {
    const held = this.claims.get(roomId);
    if (!held || (held.userId !== userId && !admin)) return false;
    this.claims.delete(roomId);
    this.changed();
    return true;
  }

  prune(exists: (roomId: string) => boolean): void {
    const gone = [...this.claims.keys()].filter((roomId) => !exists(roomId));
    if (gone.length === 0) return;
    for (const roomId of gone) this.claims.delete(roomId);
    this.changed();
  }

  subscribe(listener: Listener): () => void {
    this.listeners.add(listener);
    return () => this.listeners.delete(listener);
  }

  private changed(): void {
    const snapshot = this.list();
    for (const listener of this.listeners) listener(snapshot);
  }
}

  } catch {
    throw new Error(t().unreachable);
  }
  if (!res.ok) throw await failure(res);
}

/** Re-renders every 30 s so "last edit" and the takeover button stay current. */

  const [now, setNow] = useState(() => Date.now());

export function RoomClaimBanner({ roomId }: { roomId: string }) {
  const m = useT();
  const can = useCan();

import helmet from '@fastify/helmet';
import type { FastifyInstance } from 'fastify';

/**
 * Headers for every response. The web app is served from this same origin and loads nothing from elsewhere
 * (fonts are self-hosted, three.js is bundled), so 'self' covers it. blob:/data: are for downloads, thumbnails and 3D textures.
 */
export async function registerSecurityHeaders(app: FastifyInstance, { https }: { https: boolean }): Promise<void> {
  await app.register(helmet, {
    contentSecurityPolicy: {
      useDefaults: false,
      directives: {
        defaultSrc: ["'self'"],
        scriptSrc: ["'self'"],
        styleSrc: ["'self'"],
        imgSrc: ["'self'", 'data:', 'blob:'],
        fontSrc: ["'self'", 'data:'],
        connectSrc: ["'self'"],
        workerSrc: ["'self'", 'blob:'],
        objectSrc: ["'none'"],
        baseUri: ["'self'"],
        formAction: ["'self'"],
        frameAncestors: ["'none'"],
      },
    },
    crossOriginEmbedderPolicy: false,
    referrerPolicy: { policy: 'strict-origin-when-cross-origin' },
    strictTransportSecurity: https ? { maxAge: 31_536_000, includeSubDomains: false } : false,
  });
}

- [ ] **Step 3: Backup and restore scripts**

`deploy/backup.sh` (POSIX sh, runs in `postgres:18-alpine`):

```sh
#!/bin/sh
# Daily pg_dump at $BACKUP_AT (container local time, TZ), keeping $BACKUP_KEEP_DAYS days.
# `backup.sh --once` takes one backup now and exits (used by the restore drill).
set -eu
dump() {
  file="/backups/glasshouse-$(date +%Y-%m-%d-%H%M).dump"
  pg_dump --format=custom --file="$file.partial"
  mv "$file.partial" "$file"
  find /backups -name 'glasshouse-*.dump' -mtime +"${BACKUP_KEEP_DAYS:-14}" -delete
  echo "backup: wrote $file"
}
if [ "${1:-}" = "--once" ]; then dump; exit 0; fi
last=""
while true; do
  today="$(date +%Y-%m-%d)"
  if [ "$(date +%H:%M)" = "${BACKUP_AT:-03:00}" ] && [ "$last" != "$today" ]; then
    if dump; then last="$today"; else echo "backup: pg_dump failed; retrying in a minute" >&2; fi
  fi
  sleep 30
done
```

A failed dump is logged to stderr and retried within the same minute window. If the window passes it is retried the next day. The runbook asks the operator to check `docker logs glasshouse-backup` weekly.

`deploy/restore.sh`:

```sh
#!/bin/sh
# Restore a pg_dump into the running stack. Usage (from deploy/): ./restore.sh /data/services/services-data/glasshouse/backups/glasshouse-YYYY-MM-DD-HHMM.dump
set -eu
dump="${1:?usage: ./restore.sh <path-to-.dump>}"
[ -f "$dump" ] || { echo "No such file: $dump" >&2; exit 2; }
echo "Stopping the web container (the database stays up)..."
docker compose stop web
echo "Restoring $dump ..."
docker compose exec -T db sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < "$dump"
echo "Starting the web container; it replays the restored log on boot..."
docker compose up -d --wait web
echo "Restored. Open the app and check a few rooms."
```
